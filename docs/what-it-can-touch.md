# What plan-review can touch

From 0.2.0 the project files live in `.plan-review/`: `config.json` for settings and `work/<id>/` for each run. Your own settings are in `config.json` in `~/.plan-review/` (`%APPDATA%\plan-review\` on Windows), which plan-review reads and `plan-review prefs grill` writes (or, with `--project`, the project's file), and plan-review writes `.plan-review/.gitignore` so the project's `config.json` is never committed. Files that 0.1.x left under `.claude/` are still read when they are the only ones, and are never changed (see the plugin README).

plan-review runs inside your Claude Code session, under your permission settings: anything an agent does through Bash or file edits goes through the same approval prompts as the rest of your session.

- **The viewer** is a local server bound to `127.0.0.1` on a random port. It reads and writes only `.plan-review/work/<id>/` in your project (the plan, comment threads, drafts, approval, and the grill's `grill.json` and `grill_drafts.json`), plus a `.plan-review/work/.gitignore` that keeps it all out of git. It has no authentication, and cross-site requests to it are not blocked yet ([#36](https://github.com/Selimmo/claude-workbench/issues/36)).
- **Your tracker**, read once at the start: `/ship` reads the issue through your logged-in `gh` (GitHub) or the Jira or Linear connector you set up in Claude Code. Nothing is written to the tracker: no comments, no status changes.
- **Git**: `/ship` creates a branch and commits only after your explicit OK. It never pushes, opens a PR or merges unless you ask.
- **Agents**: all five can read your project and run shell commands, so your permission prompts are the real limit. The architect is told to write only `plan.json`, but has a Write tool. The implementer edits files and runs your configured checks. The reviewers (the built-in two and any you add) have no edit tools, and `/ship` discards any review that changed a file. The one exception is the optional mutation testing, off unless you set `mutation` in `config.json`: then the test reviewer copies your working tree, untracked files such as `.env` included, into a new folder in the system temp folder, breaks lines and runs your tests only there, and deletes the copy afterwards. Nothing in your project changes.
